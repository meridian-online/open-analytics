# NAICS 2017 to 2022 concordance: design

## Intent

Much federal data is still coded in NAICS 2017: County Business Patterns through 2023 codes industries as `NAICS2017`, and Census moves most programmes to 2022 only by the end of 2027. An analyst holding that data needs Census's own concordance to move it onto `census/naics_2022`. This Protocol hosts it as the edition crosswalk `census/naics_2017_to_2022`, in the shape the SOC edition crosswalks set (`bls/soc_2010_to_2018`, `ons/soc_2010_to_2020`).

Done when the crosswalk reads at its address, every 2022 code it names is a code in `census/naics_2022`, and its dataset page is live. This branch reaches the first two as far as a build can: the Protocol and its tests merge first, and the publish follows the merge, as FIPS, OurAirports and the NAICS index did, because CI holds every committed descriptor to the object the lake serves.

## The source, measured 2026-11-17

Census's `2017_to_2022_NAICS.xlsx`, fetched from <https://www.census.gov/naics/concordances/2017_to_2022_NAICS.xlsx> with Meridian's User-Agent (200, 59,656 bytes); one sheet, `2017 to 2022 NAICS U.S.`:

- Row 1 is a title, `2017 NAICS U.S. Matched to 2022 NAICS U.S. (Full Concordance)`; row 2 a note on what bold and italics mean; row 3 the header `2017 NAICS Code`, `2017 NAICS Title (and specific piece of the 2017 industry that is contained in the 2022 industry)`, `2022 NAICS Code`, `2022 NAICS Title`.
- Rows 4 to 1153 are 1,150 pairings, no pair repeated: 1,057 distinct 2017 codes and 1,012 distinct 2022 codes, which are all 1,012 national industries of `census/naics_2022`. Codes are stored as numbers.
- Nine 2017 industries split across several 2022 ones; 79 2022 industries take pieces of several 2017 ones. Where Census names the piece, the 2017 title carries it after ` - ` (`Anthracite Mining - anthracite surface mining`), on 21 rows.
- Two titles end in spaces. One 2017 title has Census's typo `excpet`, which the reverse file corrects.
- Columns E to I hold 19 cells of whitespace and nothing else.
- The file states no release. Its workbook properties carry Excel's save time (2021-11-16), which is not Census's statement of a revision.

Census's `2022_to_2017_NAICS.xlsx` holds the same 1,150 pairs; its texts differ from the forward file's only on the two rows above (trailing spaces, the typo).

## Goals

- `census/naics_2017_to_2022`: one row per pairing Census publishes, the crosswalk contract's seven columns and nothing after them.
- The run holds every `to_code` to the national industries of the code list built in the same Run with `census/naics_2022`'s own model, and every `from_code` to six digits.
- `arc test` tests in `tests.yaml` against cut-down Census workbooks, in CI's `protocol-tests` matrix.
- The Protocol ends in arc's publish step, as every hosted list now does.

## Non-goals

- No publish from this branch, and no committed descriptor, registry entry or README row: those come with the first publish, after the merge and Hugh's go-ahead.
- No weights. Census gives none, and Meridian does not invent them.
- No 2022-to-2017 table: the reverse file holds the same pairs, so the one table answers both directions.
- No pairing Census did not publish.

## Anti-goals

- A crosswalk that reads as more than Census said: invented weights, a corrected typo presented as Census's text, or pairings inferred from shared titles.
- A first 2017 edition in the lake that implies Meridian hosts NAICS 2017 as a code list.

## Approaches

1. **The crosswalk alone, carrying Census's 2017 titles (chosen).** `from_description` is Census's text in the crosswalk, which for a split industry names the piece that went to each 2022 industry. The 2017 codes are checked by shape alone, as SOC's 2010 codes are. One table, one Protocol, in the NAICS index's single-table layout.
2. **A `census/naics_2017` code list beside it.** It would let the run check every 2017 code against the edition, and give analysts the 2017 titles and descriptions as a list. It is a second Protocol, a second dataset to keep, and it introduces a 2017 edition as a hosted list on the strength of a bridge; nothing in the issue asks for 2017 data to be joined to anything but the crosswalk.
3. **Both directions as two tables.** The reverse file holds the same pairs, so a second table would repeat the first in another column order.

Approach 1 follows the SOC crosswalks and keeps a 2017 code list a separate decision for when an analyst needs one.

## Rulings made on Hugh's behalf (Hugh away; each undoable before the first publish)

1. **2017 titles ride on the crosswalk; no `census/naics_2017` code list.** As above. Undo: add a code-list Protocol and point the crosswalk's `from_code` check at it.
2. **The address is `census/naics_2017_to_2022`**, source side first as bearing's naming decision and Census's file name have it.
3. **The forward file only.** Its pairs equal the reverse file's; it is the direction the issue names.
4. **Texts as Census prints them, trimmed at their ends.** The typo `excpet` stays, and its field description says Census's reverse file spells it correctly. The ` - piece` suffix stays in `from_description`, since it is Census's statement of which part moved.
5. **Seven columns and no more.** Census's bold and italics mark merges and splits; both are a `count(*)` over the table, so no flag columns are added, as BLS's crosswalk has none for its `(#)` marks.
6. **`release` is `2022`**, the edition the crosswalk bridges to, as the NAICS index's is: Census's file states no release, and its save time is not one.
7. **`load` refuses a non-blank cell beyond column D**, so a column Census adds (a weight, a note) fails the run instead of being dropped unseen. The 19 whitespace cells pass.

## The Protocol

`datasets/naics_2017_to_2022/`, the NAICS index's single-table layout: `arcform.yaml`, `models/`, `tests.yaml`, `testdata/`, `descriptor.overrides.json`, `nominations.finetype.json`, `schema.finetype.json`, `.gitignore` (with `build/` and `datapackage.json`), `.env.example`, `README.md`.

Steps: `fetch_concordance` and `fetch_naics` (`http_fetch@1`, Meridian's User-Agent); `load_naics` (`sql: ../naics/models/load.sql`); `load` (`models/load.sql`); `crosswalk` (`models/crosswalk.sql`); `export_naics_2017_to_2022` (`parquet_export@1`, ordered by `from_code, to_code`); `describe`; `check_inputs` (`models/check_inputs.sql`: `contract_code_list` over `naics`, `contract_crosswalk` over the staged Parquet, shape `^[0-9]{6}$` at `national_industry`); `check_crosswalk` (`../../contracts/check_crosswalk.sql`); `validate`; `stamp_descriptor`; `publish` (`ducklake_write@1`, table `census.naics_2017_to_2022`, readable copy `census/naics_2017_to_2022.parquet`).

`load` checks the title in A1 and the header in A3:D3 before reading data, reads A4:D as text by explicit range, and fails on a pairing missing either code or either title, a code that is not six digits, and a non-blank cell in E:I. It numbers no rows.

The descriptor carries `x-meridian-crosswalk: {"from": "2017", "to": "2022", "toCodeList": "census/naics_2022"}`, primary key `(from_code, to_code)`, `other-pd` for the U.S. Census Bureau, and field constraints: both codes six digits, editions as enums, `release` enum `2022`.

## Tests

One pass case over the fixture (row count, pairs per split and merge, the piece text, trimmed ends, the typo kept, editions and release on every row, every `to_code` a national industry of the run's code list, the contract's row count) and refusals for: a moved title, a moved header, a code that is not six digits, a pairing missing a 2017 code, one missing a 2022 code, a stray value beyond column D, a 2022 code the code list lacks, and a repeated pair.

## Wiring
